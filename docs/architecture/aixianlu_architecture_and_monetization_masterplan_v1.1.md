本文档为您在本地已搭建的评测网站基础之上，制定了全面的系统架构规划、现阶段 MVP 落地策略以及未来的商业变现演进路线。技术栈确定为 **Drupal (后端内容与数据管理) + Flutter (全平台前端与客户端表现)**。

## 一、 系统架构规划 (Architecture Plan)

整体架构采用经典的**前后端分离模式**，兼顾 Drupal 强大的内容管理（CMS）与 SEO 优势，以及 Flutter 高性能、跨平台的现代 UI 体验。

### 1. 核心架构拓扑

*   **后端核心 (Drupal 10/11)：**
    *   部署在海外轻量云服务器（如 Aliyun/AWS 海外节点）。
    *   通过 Drupal 的自定义实体（Custom Entity）和 REST API 模块，负责管理：
        1. **商家/机场资料库**（名称、返佣链接、线路架构、风险标注）。
        2. **众包测速指标数据库**（接收探针上报的延迟、丢包、AI 连通性数据）。
        3. **SEO 文章与避坑指南内容库**（利用 Drupal 的 Taxonomy 与 Node 系统沉淀长尾搜索流量）。
    *   **性能增强建议**：探针上报会带来较高写入频率。建议在 Drupal 前增加轻量缓冲层——使用 Redis（或 Drupal Cache API + Redis）做指标热点缓存；探针上报优先走独立高性能入口（Go 轻量 ingest service 或 Cloudflare Workers），再异步写入 Drupal 实体，避免直接打满数据库。

*   **前端核心 (Flutter Web)：**
    *   作为 `aixianlu.com` 的主站 UI，编译为高性能静态 Web 应用托管于 **Cloudflare Pages**。
    *   通过 JSON API 实时拉取 Drupal 后端的动态信誉排行榜、评测文章与筛选结果。
    *   **部署优化**：开启 Cloudflare 智能缓存 + 边缘函数，对榜单数据做短时缓存（30–60 秒），显著降低对 Drupal 的请求压力。

*   **分布式数据源 (Open Source Probes)：**
    *   运行在用户本地或测试服务器上的轻量开源探针（Go/Python CLI），定时拉取配置、测试各大节点对 `api.openai.com`、`claude.ai` 及其他关键 AI 端点的连通性，并通过安全的 API 自动上报至 Drupal 后端。
    *   **安全要求**：探针必须实现设备指纹 + 限流 + 防刷机制（建议采用基于时间窗口的 token 或简单 challenge-response），防止恶意刷分。

*   **API 设计原则**：尽早定义稳定的版本化 API（如 `/api/v1/merchants`、`/api/v1/metrics/latest`），并加入简单的签名/API Key 机制，方便 Flutter、探针及后续第三方调用。

### 2. 架构优化总结

优先采用「轻量 Drupal 模块 + 独立 Go/Python 探针中继」的混合模式，既保留 CMS 与 SEO 优势，又避免实时写入拖慢核心系统。整体保持可演进性，后期可无缝升级为更完整的实时数据管道。

## 二、 现阶段 (Phase 1: MVP 启动与验证期) 架构规划

在本地现有评测网站的基础上，现阶段的核心目标是**“极速上线、验证数据闭环、跑通变现漏斗”**。

### 1. 数据流与功能闭环

*   **内容录入：** 初期由您在 Drupal 后台手动录入 5-8 家经过严格尽调的优质专线机场，并撰写第一批硬核长尾 SEO 评测文章（如 `Cursor 无法连接的解决方法`）。
*   **测速与信誉：** 建立基础的“静态+半自动”指标展示（初期如果探针未完全铺开，可结合人工每日测试录入，后期无缝切换为探针自动上报）。人工测试结果建议公开测试方法与截图/命令行输出，以快速建立早期信任。
*   **导购转化：** 页面所有“前往购买/查看详情”按钮统一绑定带有 Affiliate 参数的跳转链接。

**MVP 优先级建议**：先做“可信静态榜 + 人工日更”，再逐步引入完整众包探针。公开可复现的测试方法比早期追求全自动更有利于建立信任。

### 2. 现阶段技术落地任务清单 (Drupal + Flutter)

1.  **Drupal 端：** 开发 `dx_aixianlu` 自定义模块，创建以下最小可行实体：
    *   `Merchant`（商家）
    *   `MetricSnapshot`（每日/每小时快照，而非原始实时数据，便于后期切换）
    *   `Review / Note`（人工评测与风险标注）
    *   暴露版本化 REST / JSON:API。

2.  **Flutter 端：** 初始化 Flutter Web 项目，实现三大核心页面：
    *   **首页 / 实时信誉榜：** 极客深色风格，支持按运营商（电信/联通/移动）和 AI 工具（Cursor / Claude / ChatGPT / Gemini）双维度筛选。一眼展示「最近 24h 成功率 / 平均延迟 / 丢包率」，并给出清晰的推荐指数与风险提示。
    *   **详情/评测页：** 定位为「决策页」而非单纯文章——对比表 + 优缺点 + 实测数据 + 带参数购买按钮 + 用户真实反馈入口（初期可人工收集）。
    *   **开源探针下载页：** 引导极客用户下载本地测速工具，并可设计简单贡献积分机制（后期可兑换详细历史数据）。

3.  **SEO 内容启动**：优先产出 8–12 篇高意图长尾文章，例如：
    *   Cursor 无法连接 OpenAI 的完整排查与专线选择
    *   Claude 在中国大陆稳定访问方案对比（2026）
    *   电信 vs 联通 AI 专线实测差异
    *   做好内链与 Affiliate 埋点。

### 3. Phase 1 执行节奏建议（4–6 周）

1. 完成 Drupal 最小实体 + REST API + 5–8 家商家录入。
2. Flutter Web 首页榜单 + 详情页上线（先用静态/半自动数据）。
3. 产出第一批 8 篇高意图 SEO 文章。
4. 设计探针上报协议与基础防刷机制，同步开源简单版探针。
5. 建立 Telegram 播报频道 + 简单用户反馈收集机制。

## 三、 数据与产品创新方向

单纯延迟与丢包已不够形成长期差异化。建议从「测速榜」逐步升级为「AI 连通性决策系统」。

### 高价值数据维度

*   **模型级连通性**：不只测域名，进一步测试具体模型端点的可用性与错误类型（rate limit、region block、TLS 问题等）。
*   **稳定性复合指标**：连续可用时长、抖动系数、高峰时段表现。
*   **场景标签**：Cursor 代码补全、Claude 长上下文、ChatGPT 多轮对话、批量 embedding 等不同场景的推荐度。
*   **风险雷达**：价格变动频率、客服响应速度、历史掉线事件、退款政策等。

### 产品创新点

*   **智能推荐**（Phase 1 可用简单规则实现）：根据用户运营商 + 常用工具 + 预算，给出「当前最优 3 家」。
*   **探针生态激励**：贡献数据的用户获得积分，可兑换更详细历史数据或优先体验新功能。
*   **浏览器扩展 / IDE 插件**（中期）：一键检测当前线路对 Cursor/Claude 的可用性，并跳转推荐——强获客入口。
*   **公开数据 API + 定期白皮书**：发布《中国大陆 AI 网络连通性与开发者痛点白皮书》，形成行业引用源，强化「第三方权威」定位。

## 四、 未来变现与生态演进 (Phase 2 & 3: 规模化与多元变现)

当 `aixianlu.com` 通过 SEO 和极客社区（V2EX / Linux.do / GitHub）积累了稳定的首批日活开发者流量后，商业模式将从「单一返佣」向「多级商业矩阵」演进。

### 1. 变现三级火箭规划（优化版）

| 演进阶段 | 变现模式 | 具体实现方式 | 预期收益占比 | 优化重点 |
| :--- | :--- | :--- | :--- | :--- |
| **阶段一 (当前)** | **基础 Affiliate 返佣** | 通过客观测速榜单和评测文章，引导用户点击带返佣的官方购买链接（首单返佣 + 持续循环续费分成）。 | **80%** | 提升转化效率：增加「对比后一键跳转」与「限时实测优惠」展示；对高转化商家做深度合作（更高返佣 + 专属测试通道）。 |
| **阶段二 (成长期)** | **B 端合规赞助与认证体系** | 随着网站成为行业公认的「第三方权威测评机构」，向通过审核的优质机场开放「透明度白名单认证」或首页置顶展位。 | **15%** | 从单纯广告位升级为「AIXianlu 透明度认证」：公开节点架构、历史可用性、客服 SLA。认证本身可收费，比广告更有公信力。 |
| **阶段三 (成熟期)** | **SaaS 级 API 智能网关与增值服务** | 面向有稳定出海与大模型调用需求的中小团队，推出「AI API 智能多路负载均衡与容灾切换网关」SaaS 服务，按企业调用量或订阅收费。 | **5% 渐增** | 做成「智能路由 + 故障自动切换 + 调用量统计 + 成本优化」的开发者工具，专注 AI 场景。 |

### 2. 长期生态护城河

*   **数据飞轮**：探针数据越多 → 榜单越准 → 流量越大 → 更多商家愿意合作 → 更多数据。
*   **数据资产化**：通过长期积累的分布式众包探针，定期发布《中国大陆 AI 网络连通性与开发者痛点白皮书》，形成行业定价权和话语权。
*   **信任资产**：所有测试方法与脱敏原始数据尽量公开可复现，建立「可审计」形象。
*   **品牌防失联矩阵**：同步运营 Telegram 实时播报频道、GitHub 开源生态与备用域名，确保在网络波动或审查严厉时期流量不丢失。
*   **社区运营**：在 V2EX、Linux.do、即刻、小红书开发者圈持续输出实测内容，而非纯导购。
